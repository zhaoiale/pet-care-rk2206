## 一、系统架构与核心原理

### 1.1 整体架构

```
┌─────────────────────────────────────────────────┐
│              OpenHarmony App (ArkTS)              │
│  Dashboard │ VirtualPet │ Comfort │ Feeding │ ... │
├─────────────────────────────────────────────────┤
│              MQTT (HiveMQ Broker)                │
├─────────────────────────────────────────────────┤
│         OpenHarmony RK2206 主控 (LiteOS-M)        │
├──────┬──────┬──────┬──────┬──────┬──────┬───────┤
│MAX30102│MLX90614│HX711│MPU6050│ATGM336H│SU-03T│MAX9814│
│心率血氧│体温  │称重  │加速度│GPS/北斗│语音识别│拾音器│
├──────┼──────┼──────┼──────┼──────┼──────┼───────┤
│BH1750│RGB LED│蜂鸣器│继电器 │SHT30│SPI Flash│        │

```

**主控**: 瑞芯微 RK2206 (OpenHarmony 3.0 LTS, LiteOS-M 内核)
**通信**: WiFi + MQTT (HiveMQ 公共 Broker)
**外接模块**: 11 个传感器/执行器，覆盖健康监测、环境感知、行为分析、主动关怀

### 1.2 核心技术原理

#### 焦虑情绪评估引擎 (Anxiety Engine v4.2)
- **6 维特征向量**: 活动量(MPU6050) + 心率(MAX30102) + HRV压力指数 + 叫声频次(拾音器) + 体温(SHT30) + 环境舒适度
- **自适应基线**: 24 小时分桶 EWMA (指数加权移动平均), 持续学习每只宠物的正常行为模式
- **加权马氏距离**: 考虑特征间相关性的多变量异常检测，权重向量 [1.2, 2.0, 2.5, 1.5, 0.8, 0.6]
- **心率-活动解耦**: 高活动+高心率=运动(降低权重0.4x)；低活动+高心率=静息心动过速(提升1.4x)
- **Sigmoid 映射**: 焦虑值 = 100 × (1 - e^(-D²/50)), 输出 0-100 分
- **情绪分级**: Happy(0-15) / Calm(16-35) / Alert(36-60) / Anxious(61-100)

#### 宠物叫声意图识别
- **ADC 裸采**: RK2206 内置 ADC 直采驻极体麦克风，~8kHz 采样率，busy-wait 精确定时
- **VAD 端点检测**: 能量自适应阈值 + 过零率统计，状态机 IDLE→ONSET→ACTIVE→OFFSET
- **特征提取**: 8 维声学特征（音节数、时长、响度、过零率均值/方差等）
- **规则决策树**: 3 类意图 — hungry(饥饿讨食) / warning(警戒吠叫) / lonely(委屈呼唤)
- **DeepSeek 增强**: 意图 + 传感器上下文 → AI 生成自然语言解读

#### 电子围栏与轨迹回放
- **Haversine 公式**: 大圆距离计算，默认半径 100 米
- **离线轨迹记录**: 256 点环形缓冲，SPI Flash 持久化，MQTT 重连后自动上传
- **simpath 命令**: 支持手动模拟 GPS 轨迹用于演示

#### 智能投喂系统
- **HX711 称重**: 24 位 ADC，实时监测食盆余量，校准系数 216.3
- **定时投喂**: Flash 持久化 3 时段计划，继电器驱动电机
- **已食量估算**: 重量变化 → 进食量统计

## 二、一分钟精简版 (电梯演讲)

> 各位评委好，我们的作品是"智宠管家"——基于 OpenHarmony RK2206 的宠物异常行为感知与主动关怀系统。
>
> 核心解决一个痛点：**主人上班时，宠物在家焦虑、饥饿、越界，主人不知道。**
>
> 我们做了三件事：
> **第一，多模态感知。** 11 个传感器实时采集心率、血氧、体温、活动量、叫声、位置，构建 6 维特征向量的焦虑评估模型，用加权马氏距离做异常检测，24 小时自适应基线学习每只宠物的正常模式。
> **第二，主动关怀闭环。** 检测到焦虑自动触发呼吸灯安抚（RGB LED 暖光）+ 蜂鸣器五声音阶摇篮曲；配合定时投喂、电子围栏越界告警，形成"感知-决策-执行"完整链路。
> **第三，AI 赋能。** 拾音器采集宠物叫声，VAD 端点检测 + 声学特征提取 + DeepSeek AI 解读叫声含义；App 端还有 AI 对话功能，用宠物口吻和主人互动。
>
> 整套系统跑在 OpenHarmony LiteOS-M 上，外设驱动用 HDF 框架，MQTT 双向通信，App 用 ArkTS 声明式 UI 开发。软硬件完全自研，谢谢。

## 六、评委问答预案

### Q1: 心率/血氧数据准确吗？有没有对标？
> "心率数据通过 MAX30102 光学传感器 PPG 信号采集，算法层面用了直流分量滤波+交流分量峰值检测。我们在调试阶段和市面上指夹式血氧仪做过对比（亮出来），心率误差在 ±5 bpm 以内。血氧我们用的是经验公式 SpO₂≈110-25×R，受限于未做大规模标定，目前作为趋势参考。这是后续可以用医用级设备标定的方向。"

### Q2: 焦虑评估的准确性怎么验证？
> "焦虑是一种主观情绪，没有黄金标准。我们的做法是：1) 用多传感器融合而不是单指标判断，降低误报；2) 24 小时自适应基线让系统学习每只宠物的正常行为模式；3) 马氏距离考虑了特征间的相关性，比简单阈值更鲁棒。从实际测试看，晃动设备模拟异常活动时焦虑值会正确上升，静止时恢复正常。"

### Q3: 叫声识别准确率多少？为什么不用深度学习？
> "目前用决策树规则分类，准确率取决于声学环境，安静环境下 3 类意图识别约 70-80%。RK2206 是 Cortex-M4 级别算力，跑不了神经网络推理。我们设计了云端增强方案——规则分类作为轻量级初筛，DeepSeek 做二次语义解读。这是一个端-云协同的架构。"

### Q4: MQTT 断网了怎么办？
> "设备端有三级本地保护：1) GPS 轨迹写入 SPI Flash 环形缓冲，重连后自动补传；2) 定时投喂计划存在 Flash 中，不依赖网络；3) 围栏越界本地触发 LED+蜂鸣器告警。核心功能不完全依赖网络。"

### Q5: 为什么用 OpenHarmony 而不是 FreeRTOS/裸机？
> "两点原因：第一，HDF 驱动框架让外设驱动开发更规范——统一的接口抽象层，代码可移植性好；第二，OpenHarmony 的应用层 ArkTS 可以快速构建跨设备 UI，未来如果需要适配智能手表或智慧屏，改动量很小。这也是鸿蒙分布式能力的核心优势。"

### Q6: 这么多传感器功耗能撑多久？
> "目前演示阶段用的是 USB 供电。实际产品化的话，MAX30102 和 GPS 是功耗大头——MAX30102 可以 duty-cycle（比如每 10 分钟采 30 秒），GPS 只在围栏检查时唤醒。配合低功耗 MCU 和电池供电，能做到一周以上的续航。这是工程化下一步的方向。"

### Q7: 和市面上的宠物穿戴设备有什么区别？
> "市面上的宠物追踪器（如小佩、Tractive）主要是 GPS 定位，缺乏多维度健康监测。我们的差异化在于：1) 不只是定位，还有心率血氧体温活动量的健康感知；2) 不只是监测，还有主动安抚和投喂的执行能力；3) 宠物叫声识别+AI 解读，这是人宠交互的新维度。"

### Q8: 项目的实际应用场景？
> "年轻人养宠物的核心痛点：上班 8-10 小时不在家，焦虑宠物是否健康、吃没吃饭、有没有拆家、会不会跑丢。我们的系统覆盖了这四个场景：健康→心率/活动监测；进食→自动投喂+称重；拆家→焦虑检测→主动安抚；走丢→电子围栏+轨迹追踪。"
